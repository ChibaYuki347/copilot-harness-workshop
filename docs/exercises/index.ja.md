# 🧪 演習

**このサイトの残りを読み終えたあとに、自分のマシンで取り組める実践課題です。** 各演習は小さく自己完結しており、「なんとなく合っていそう」ではなく、うまくいったことが客観的に確認できる形で終わります。

## このトラックの構成

演習は段階的に積み重なるようにできています。順番どおりに進めると、ある演習で作った成果物を次の演習で再利用できます。さらに **キャップストーン** では、そのうち 4 つを 1 本の動くパイプラインにまとめます。

| # | 演習 | レイヤー | 難易度 | 時間 |
|---|---|---|---|---|
| 1 | [カスタムインストラクション](01-custom-instructions.md) | 常時適用コンテキスト | 🟢 入門 | 約20分 |
| 2 | [プロンプトファイル](02-prompt-files.md) | 再利用可能なプロンプト | 🟢 入門 | 約25分 |
| 3 | [スキル](03-skills.md) | 再利用可能なワークフロー + スクリプト | 🟡 中級 | 約45分 |
| 4 | [MCP サーバー](04-mcp.md) | 外部ツール | 🟡 中級 | 約30分 |
| 5 | [カスタムエージェント](05-agents.md) | 専門家への委譲 | 🟡 中級 | 約30分 |
| 6 | [フック](06-hooks.md) | ライフサイクル自動化 | 🟡 中級 | 約30分 |
| ✨ | [キャップストーン — リリースノートパイプライン](capstone.md) | 以上すべて | 🟡 中級 | 約45分 |

## 始める前に

!!! warning "スクラッチ用のリポジトリで作業してください"
    大事なリポジトリでこれらの演習を行わないでください。新しいものを 1 つ用意します:

    ```bash
    mkdir ~/copilot-harness-lab && cd "$_"
    git init && git commit --allow-empty -m "init"
    ```

    どの演習も、安全にファイルを作成できる git リポジトリの中にいることを前提にしています。

必要なもの:

- **Copilot CLI** のインストールと認証。詳しくは [はじめに → インストール](../getting-started/installation.md) を参照してください。
- **`git`** と最近の shell。フックの演習では `bash` を使います。macOS / Linux / WSL のいずれでも動きます。
- **`gh` CLI**（任意）。必要なのはプロンプトファイル演習とキャップストーン演習の *発展課題* だけです。

## 各ページの構成

どの演習ページも同じテンプレートで書かれているので、毎回同じ見方で素早く読めます:

1. **学習目標** — 最後に何ができるようになるか。
2. **時間と難易度** — どの程度の作業になるか。
3. **前提条件** — 必要なファイル、アカウント、ツール。
4. **チェックポイントコミット** — `git commit -am "before-exercise"` をしておくと、やり直したくなったときに `git reset --hard` できます。
5. **シナリオ** — 問題設定を 1 段落で示します。
6. **手順** — 番号付きで並び、各手順に確認できる結果があります。
7. **完了条件** — 客観的なチェックリストです（コマンド、ファイル、終了コードなど）。
8. **参考解答** — 折りたたみ式です。[`examples/`](https://github.com/ChibaYuki347/copilot-harness-workshop/tree/main/examples) のスニペットを優先しているので、実際のファイルをそのままコピーできます。
9. **クリーンアップ** — 追加したものを削除する方法です。
10. **トラブルシューティング** — 起こりやすい失敗パターンを 2〜3 個に絞って扱います。
11. **やってはいけないこと** — あとで効いてくる落とし穴です。
12. **発展課題** — さらに広げるための 1〜3 個のアイデアです。

## 検証について

ほとんどの演習は「Copilot の返答が *それっぽいか*」ではなく、**コマンド** で検証します。繰り返し登場する便利な組み込み確認方法は次のとおりです:

| コマンド | 分かること |
|---|---|
| `/env` | このセッションでどのインストラクション / スキル / エージェント / フック / MCP サーバーが読み込まれたか。 |
| `/instructions` | 現在のスコープに入っているインストラクションファイル。 |
| `/skills` | 読み込まれているスキル。 |
| `/mcp show` | 接続されている MCP サーバーと、そのツール。 |
| `/agent` | 使えるものを確認できるカスタムエージェントピッカー。 |
| `copilot --debug …` | ツール呼び出し、フック発火、MCP 通信のストリーム。 |

正しいファイルが読み込まれていれば `/env` に表示されます。表示されないなら、問題は **検出** であってモデルではありません。

## クリーンアップ

各演習の最後には **クリーンアップ** ブロックがあります。途中で止めた場合の最短リセットは次のとおりです:

```bash
git restore --staged . && git checkout -- . && git clean -fd
```

…スクラッチ用のリポジトリ内でこれを実行します。演習で作成したファイルをすべて元に戻せます。
